# QingCS 电影级导演书、分镜与预演

## 方法来源

本技能按 QingCS 项目需要，吸收并重组市面开源电影生产方法，不照搬具体影片或具名导演风格：

- `wuwangzhang1216/DirectorSKILL`（Cinematic Director Skill v2.0，MIT）：镜头是叙事决定；先走位后构图；关键帧是控制点；连续性必须工程化；失败后定位问题而不是盲目重抽。
- `calesthio/generative-media-skills` 的 `storyboard-previsualization`：先验证故事节拍、空间、构图、动作、剪辑、时长、声音和连续性。
- `game-cinematic-cutscene-design`：检查镜头功能、可读性、180度轴线、视线、屏幕方向、声音和场景交接。
- `higgsfield-ai/skills`：使用具体可见的镜头语言；图生视频重点描述运动，不重复静态画面。

本项目只继承工作方法，保持原创的职业现实主义、程序性悬疑和平行大清工业景观。

## 核心原则

分镜不是“漂亮画面清单”，而是可执行的电影预演。每个镜头都必须让观众多知道、感到或预期一件事；删掉后如果故事没有损失，这个镜头就不该存在。

顺序固定为：

`正文与潜台词 → 节拍图 → 导演书 → 人物走位 → 镜头表 → 关键帧 → H3适配 → 声音/剪辑 → QC`

不得从正文直接跳到“24mm、推镜、电影感”提示词。

## 交付物

每章分镜生产两份文件：

1. `分镜/第NN章_导演书与镜头表.md`：控制戏剧问题、潜台词、视觉命题、表演、走位、焦段、光线、声音、连续性、关键帧和失败修正。
2. `分镜/第NN章_十格分镜.md`：把导演书适配为10格×15秒的MiniMax H3生产单元。

15秒是一段剪辑单元，不等于一个电影镜头。每格可拆成1—4个短镜头，但只能完成一个主要叙事节拍。

## 导演分析

开始前回答：

- 表层发生了什么？
- 本场真正的戏剧问题是什么？
- 外部冲突和内部冲突是什么？
- 人物没有直说的潜台词是什么？
- 情绪从什么状态移动到什么状态？
- 哪个视觉命题能用可见行为表达，而不是靠旁白解释？

## 走位先于构图

每个镜头先写：

`人物起点 → 看到什么 → 做什么 → 停在哪里 → 看向哪里 → 道具最后在哪只手/哪个位置`

再决定相机。空间影响动作时，先给全景、中景或稳定锚点；不能用一串特写掩盖人物地理不清。

## 镜头硬规则

- 每镜只有一个主要故事功能、一个主动作、一个主要机位行为；环境运动也只保留一个重点。
- 动作必须写到结束状态，例如“后退到椅背碰膝并停”，不能只写“她后退”。
- 镜头运动必须有叙事工作：推近逼近决定，拉远暴露孤立，横移揭示关系，手持表现失稳；禁止为“电影感”而移动。
- 景别服务信息：全景看地理，中景看关系与动作，近景看反应，特写/插入看证据。
- 守住180度轴线、视线和屏幕方向；有意越轴必须经过中性机位或可见移动。
- 对话镜头先写“谁听见什么、反应在哪一拍改变”，再写台词；关键决定、认人和拒绝必须留反应拍。
- 不写抽象情绪“她很害怕”，写手抖、停呼吸、后退、避开触碰、盯住出口等可拍行为。

## 关键帧控制

高风险镜头必须先过关键帧门槛，再进入视频生成：

- 多人群像与固定站位；
- 人物身份和脸部连续性；
- 精确手部、奖牌、卡片、鼠标和名册；
- 现代房间与平行大清同机位叠化；
- 首尾状态差异明显的匹配切换。

关键帧检查：构图是否说清故事、人物是否站对位置、视线和光向是否连续、关键道具是否可追踪、文字是否留后期合成安全区。关键帧不过，不继续生成视频。

## 角色反应规则

当主角表现异常时，旁人只能依据眼前证据判断：

- 先解释为输图应激、撞伤、低血糖、记忆混乱、开玩笑或逃避复盘；
- 先吐槽或追问，发现主角没有配合玩笑后再担心；
- 队长控制现场，入口位先照顾人，主狙核对物证，断后位查时间与记录，赛务员暂停流程，医务值守做定向和伤情检查；
- 不能集体理解“她是穿越者”，也不能替主角解释身份或国家认同。

## 声音与剪辑

- 用J-cut预告下一空间，用L-cut保留上一情绪；切点来自枪声、动作方向、视线、形状、光线或声音。
- 每场先确定稳定声音底床，再加入变化；异常通过重复、延迟和来源转移推进，不用廉价惊吓音。
- 一段15秒内对白过多时，删说明、用插入证据和画外音表达，或明确拆镜；禁止加速念台词。
- 精确比分、名册和赛务字段以后期合成为主，生成画面只保留版面和文字安全区。

## 连续性圣经

每章固定：

- 角色脸型、发型、体态、服装、饰物和职业动作；
- 场景平面、门、桌、设备、光源和人物初始位置；
- 主色调、光线方向、景深和焦段范围；
- 道具由哪只手持有、朝向和当前状态；
- 每镜轴线、视线和移动方向；
- 年代、比分、名单、时间和人物已知信息；
- 禁止变化：真人肖像、真实队标、随机文字、换装、角色漂移、道具凭空出现。

## H3适配字段

每格固定写：

1. 叙事任务与观众问题；
2. 稳定镜头编号、时长、景别/焦段、故事功能、走位和动作终点；
3. 表演变化；
4. 声音与剪辑；
5. 连续性与通过标准；
6. `SCENE / ACTION / CAMERA / BLOCKING / PERFORMANCE / AUDIO / TRANSITION / CONTINUITY / NEGATIVE`。

图生视频时，只写相对起始关键帧的运动和变化，不重新描述整张静态画面。

## 失败诊断

生成失败后先分类，只改对应层：

- **故事失败**：观众不懂发生了什么 → 重写节拍或删镜头。
- **空间失败**：人物位置/轴线混乱 → 重做主镜头和走位。
- **表演失败**：角色反应像知道作者真相 → 重写可见刺激和反应顺序。
- **连续性失败**：脸、服装、道具、光向漂移 → 加强参考图和连续性串。
- **运动失败**：镜头/人物动作过多 → 每镜只留一个主运动并写终点。
- **文字失败**：模型乱字 → 移除生成文字，改为后期合成。

不得用“再抽一次也许会好”代替诊断。

## 审核顺序

1. 故事与观众更新；
2. 空间、走位和轴线；
3. 表演是否来自人物已知信息；
4. 15秒节奏和反应拍；
5. 声音与剪辑动机；
6. 关键帧与生成可行性；
7. 连续性；
8. 正文—导演书—十格分镜—下一章接口一致性。

完成当前章后立即停止，不提前制作下一章。

## Higgsfield官方技能接入层

`higgsfield-ai/skills`适合接在**导演书和关键帧之后**，负责模型选择、身份参考、图生视频运动和成片迭代；它不能替代节拍、走位、轴线和表演设计。

### 可吸收的方法

- **同一身份参考贯穿多镜。** 先定角色标准照、服装、发式、场景关键帧，再在每个镜头复用同一组参考；不要只靠“same character”四个字。
- **图生视频只描述变化。** 起始图已经包含人物和场景时，提示词重点写动作、表情变化、镜头运动、风、烟、布料和结束状态，不重述整张画面。
- **起始帧与结束帧控制。** 空间叠化、门开合、转身和匹配切换优先准备首尾关键帧；不能让模型凭长提示自由猜终点。
- **短提示优于堆词。** 每镜保留主体、动作、相机、表演、声音/氛围和连续性锚点，删除同义形容词；复杂动作拆镜。
- **模型能力按镜头风险选择。** 多人群像、身份连续、复杂运动、精确手部、文字与UI不能用同一套默认策略；先判断是故事问题、模型问题还是需要后期合成。
- **样片先于精修。** 先做低成本关键帧/短样片/animatic确认节奏，再提高分辨率；只重做失败镜头，不整章随机重抽。

### QingCS固定工作流

1. 从人物档案和`23_全员外貌性格与古风发式深化.md`建立角色参考包。
2. 从导演书选出高风险关键帧：群像、手部、证件照、奖牌、现代/大清同机位叠化。
3. 每个镜头建立“起始状态—唯一主动作—结束状态”。
4. 图生视频提示只写相对运动，并复用固定连续性串。
5. 比分、门禁、名册、临时卡和印章文字全部留安全区，后期合成。
6. 先剪animatic，确认对白有反应拍、观众能看懂地理，再生成高质量片段。
7. 若身份漂移，增加角色参考；若空间漂移，改用锁机和首尾帧；若动作坍塌，拆镜；若文字错误，移交后期。

### 每镜生成字段

`REFERENCE / SCENE / ACTION / CAMERA / BLOCKING / PERFORMANCE / END STATE / AUDIO / CONTINUITY / NEGATIVE`

其中`REFERENCE`和`CONTINUITY`必须跨镜稳定，`ACTION`和`END STATE`只描述本镜变化。

## 明清化比赛三层分镜扩展

凡章节出现穿越后的比赛、训练、游戏内回放或直播，先调用 `qingcs-mingqing-match-visual`，不得由分镜技能临时发明地图、枪械或比赛化身。

### 三层标记

每个比赛短镜头增加 `LAYER`：

- `REAL_STAGE`：现实赛台、身体、键鼠、耳机、队内语音、暂停与后果；
- `GAME_BATTLEFIELD`：明清化地图、比赛化身、枪械、道具与战术动作；
- `OBSERVER_INFO`：观察者视角、UI、回放、太监解说和公众版本。

同一短镜头原则上只有一个主层。跨层镜头必须写明起始层、切点和结束层，禁止用模糊“进入游戏世界”替代具体匹配切换。

### 首次完整揭示节拍

穿越后的第一场正式比赛至少包含：

1. 现实五席与设备地理；
2. 回合开始的声音切点；
3. 屏幕、门洞、准星、手腕或光线匹配；
4. 游戏地图总览；
5. 比赛化身与基础武器识别；
6. 一次能看懂的烟闪/补枪或残局；
7. 太监解说提供普通读者入口；
8. 高光/失误后回到现实手部或队友反应；
9. 观察者回放解释证据与下一轮经济。

后续比赛可以压缩，但每个主要回合仍要让观众知道地图位置、人数/时间、关键选择和代价。

### 地图、武器和化身连续性

比赛连续性圣经追加：

- `MAP_ID` 与固定 A/B/MID 地理；
- 主要通道的屏幕方向和回防方向；
- `WEAPON_ID`、基础型号、角色版本和当前弹匣状态；
- `AVATAR_ID`、战术服、装备位置、发型与身份母版引用；
- 烟、闪、火的起点、轨迹、落点与剩余时间；
- C4 的持有人、落点、安放和拆弹状态；
- 现实赛台手部与游戏动作的匹配锚点。

标准空手定妆不作为持械动作参考；比赛化身也不能替代身份母版。

### 太监解说与观察者分镜

每句太监解说固定写：

- `EUNUCH_CAST_ROLE`：唱局／评策／掌镜／录局；
- `KNOWN_INFO`：此刻合法知道的信息；
- `LINE_FUNCTION`：报事实／解释因果／修正判断／转场／制造公共版本；
- `AUDIO_PRIORITY`：是否让位于枪声、脚步、队内语音或拆包音；
- `OBSERVER_VIEW`：第一人称／自由镜头／俯视图／回放；
- `END_STATE`：观众多懂了什么。

太监解说是专业岗位，不使用尖嗓、娘化、身体羞辱或猥琐刻板印象。唱局先报发生了什么，评策再说为什么重要；现场判断、回放证据和赛务结论不能混成一句。

### UI 与文字

精确比分、地图名、选手名、经济、击杀栏、字幕、准星数值和赛务字段全部后期合成。关键帧只生成干净版式和 `UI_SAFE_AREA`。长对白优先画外音、侧背影或短口型，不依赖模型准确生成整段口型。

## 比赛 H3 附加字段

比赛格在原字段后追加：

```text
LAYER:
MAP_ID:
MAP_POSITION:
WEAPON_ID:
WEAPON_STATE:
AVATAR_ID:
PRIMARY_TACTICAL_ACTION:
OBSERVER_VIEW:
OBSERVER_QUESTION:
EUNUCH_CAST_ROLE:
KNOWN_INFO:
LINE_FUNCTION:
AUDIO_PRIORITY:
UI_SAFE_AREA:
REALITY_RETURN:
```

图生视频时只描述相对关键帧的变化：角色移动到哪里、枪口如何变化、烟如何扩散、镜头切向何处、解说何时进入或让位，以及结束状态。不要重述整套地图和武器设定。

## 比赛失败诊断

- **层级失败**：现实、游戏和 UI 混成同一空间 → 给每镜重标 `LAYER` 并重做切点。
- **战术失败**：只剩漂亮枪战，观众不懂位置 → 补地图锚点、人数/时间和选择代价。
- **地图失败**：通道与包点漂移 → 回到批准 `MAP_ID` 总览和屏幕方向。
- **武器失败**：枪械跨镜变形 → 锁 `WEAPON_ID`、基础型号和角色版本参考。
- **化身失败**：角色脸或服装漂移 → 同时锁身份母版与 `AVATAR_ID`，不要只写角色名。
- **动作失败**：开火、换弹、拉栓、投掷混在一起 → 拆成单一主动作和明确终点。
- **解说失败**：像宫廷小品或全知旁白 → 删除刻板印象，重写合法信息、事实和因果。
- **UI失败**：乱码和假数据 → 清空文字，保留后期安全区。

比赛分镜交付前确认：三层清楚、地图可读、武器连续、角色动作符合位置、太监解说合法专业、精确文字后期合成、高光回到现实后果。
