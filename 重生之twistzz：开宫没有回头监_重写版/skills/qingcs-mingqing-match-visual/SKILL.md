# QingCS 明清化比赛战场与武器视觉生产

## 核心目标

把穿越后的比赛视觉稳定生产为三层系统：

1. **现实赛台层**：选手、键鼠、耳机、宫廷电竞硬件和真实后果；
2. **游戏战场层**：明清化原创地图、现代枪械、比赛化身和战术动作；
3. **观察者信息层**：OB 切镜、UI、回放、太监解说和公共版本。

采用“战术骨架保留、视觉重新设计”。视觉必须让观众同时认出 CS 战术用途与 QingCS 平行大清身份。

## 必读资料与优先级

冲突时按以下顺序裁决：

1. 用户本轮明确要求；
2. `设定/09_明清化游戏战场与枪械视觉设定.md`；
3. `设定/10_太监解说与观察者信息层设定.md`；
4. `设定/11_明清比赛视觉资产清单.md`；
5. `人物档案/24_比赛化身与武器绑定总表.md`；
6. `提示词/明清化比赛地图与武器提示词总表.md`；
7. 指定角色身份母版与人物档案；
8. 既有世界观、比赛叙事和现实宫廷电竞场景设定。

旧现实比赛殿、训练房、服务器房和角色空手定妆图不能覆盖游戏战场规则。现实游戏截图和真人职业照只能用于内部研究，不能进入公开资产。

## 资产路由

开始前先判定唯一 `ASSET_TYPE`：

- `MAP`：地图环境与战术地理；
- `WPN`：基础武器型号或角色武器版本；
- `UTL`：烟、闪、雷、火、C4、拆弹器；
- `AVT`：比赛化身与持械动作；
- `OBS`：观察者 UI、俯图、回放、经济板；
- `CAST`：太监解说、掌镜和录局资产；
- `KF`：漫剧比赛关键帧与三层切换。

一次任务只生产一个主资产。用户要求“做一场比赛概念图”时，也要先选一个关键帧，而不是在一张图塞完整地图、十名角色、全部枪械、解说席和 UI。

## 身份母版分流硬锁

`qingcs-ancient-character-visual` 负责标准空手身份母版；本技能负责比赛持械资产。

- 标准定妆：双手完整可见且空置，无武器、弹匣、手雷、枪带和武器影子；
- 比赛化身：允许持指定武器与道具，但必须复用已批准脸型、发型、体态和主色；
- 不得用比赛海报反向修改身份母版；
- 不得为了表现职业位置，在标准定妆里加入枪匣或武器；
- 用户同时要求“空手三视图＋持枪动作”时，拆成两个独立资产任务。

## 地图生产工作流

### 1. 锁战术骨架

在写视觉词前先填写：

```text
ATTACK_SPAWN:
DEFENSE_SPAWN:
A_SITE:
B_SITE:
MID:
LONG_SIGHTLINE:
CLOSE_CONTEST:
PRIMARY_ROTATION:
RISKY_FLANK:
SMOKE_CUTS:
FLASH_ENTRIES:
FIRE_DENIAL:
HEIGHT_RELATION:
```

缺少 A/B 点、中路或回防关系时，停止生成。

### 2. 选择明清空间类型

只能从能支撑战术的空间出发：边关、王城外廓、府城巷道、机造总局、皇陵外城、漕运货栈、御河水工、营造工地等。不要默认所有地图都是金碧皇宫。

### 3. 把掩体变成工作物件

优先使用：军械箱、粮包、石栏、木车、货架、锅炉、轨道车、维护架、沙袋、工装平台、残墙和门体。禁止随意摆花瓶、屏风、香炉和宝座充当掩体。

### 4. 先总览，后拆点

顺序固定：

1. 斜俯视战术总览；
2. A 区关键视角；
3. B 区关键视角；
4. 中路/主信息线；
5. 俯视战术图；
6. 道具空间；
7. 正式灯光基准。

总览看不懂，不生产角色交火图。

### 5. 地图 QC

- 是否可一眼找到 A/B/MID？
- 长视线与近战线是否同时存在？
- 回防路线是否真实可走？
- 烟、闪、火是否有合理作用面？
- 门洞、台阶和掩体是否符合人物尺度？
- 明清材料是否服务枪战而不是遮挡人物？
- 是否像原创战术地图，而非现实游戏截图贴皮？

## 武器生产工作流

### 1. 读取基础结构

先写功能清单，不先写纹样：

```text
SILHOUETTE:
BARREL:
RECEIVER:
MAGAZINE:
STOCK:
HANDGUARD:
SIGHT_OR_SCOPE:
ACTION_OR_BOLT:
SUPPRESSOR:
GRIP_POINTS:
RELOAD_PATH:
EJECTION:
```

任何装饰都不得删除或改变这些结构。

### 2. 应用材料语言

- 结构：黑化钢、乌铁、磨砂金属；
- 护木/枪托：赤漆木、乌木、灰白硬木、深黛复合材料；
- 接口：少量黄铜；
- 纹样：低对比云雷、冰裂、回纹、城垛纹；
- 软件：深色皮革与织带；
- 磨损：握持、架枪、换弹、枪口热和运输。

禁止用黄金、玉石、龙头和蒸汽管线证明“古风”。

### 3. 基础型号先于角色版本

先通过 `WPN-xx` 基础设定板，再做 `WPN-xx-CHAR-角色名`。角色版本只能改变枪带、磨损、职责标、小刻线和保养状态，不能改变枪管、弹匣、机匣、瞄具和操作路径。

### 4. 必需视图

武器设定板至少包含：左、右、3/4、第一人称、关键机械、材质磨损和一个动作关键状态。AWP 的开火与拉栓必须分帧；换弹必须有起始和结束状态。

### 5. 武器 QC

- 是否仍一眼认出通用枪名？
- 弹匣、瞄具、消音器和枪托位置是否正确？
- 握持与换弹是否可执行？
- 装饰是否避开机械运动和手部？
- 是否错误变成火绳枪、燧发枪、弓弩或仙侠法器？
- 是否出现现实品牌、皮肤、队标或随机铭文？

## 比赛化身工作流

### 1. 锁身份引用

读取指定角色的已批准母版，提取：

`脸型 / 发型 / 发际线 / 体态 / 肩线 / 身高感 / 主色 / 固定识别物 / 年龄段`

不从真人照片直接生成最终比赛化身。

### 2. 翻译为战术服

- 袖口收紧；
- 下摆不过膝；
- 鞋底适合跑动；
- 护具不过度厚重；
- 弹匣与道具位置符合角色职责；
- 发型能戴耳机、伏身和开镜；
- 原身份识别物改为固定式、轻量、无手持版本。

### 3. 绑定职业选择

角色姿态必须来自位置：

- 二号位：保持补枪距离；
- IGL：观察队友与资源，不边开枪边夸张指挥；
- 主狙：稳定肩线、开火与拉栓分帧；
- 首接触：向前但保留补枪接口；
- lurk：静步与信息来源可解释，不使用隐身；
- 支援：投掷后进入补枪或覆盖位置。

### 4. 一镜一个主动作

从以下选择一个：`IDLE / RUN / WALK / CROUCH / AIM / FIRE / RELOAD / UTILITY / OUT / REALITY_MATCH`。禁止同一帧开火、换弹、投雷和转身。

### 5. 化身 QC

- 身份是否与母版一致？
- 战术服是否能完成动作？
- 武器是否调用正确基础型号？
- 手部、枪托、贴腮和枪口是否正确？
- 职业位置是否通过动作而不是标签体现？
- 是否误用现实队服或真人肖像？

## 观察者信息层工作流

### 1. 先确定观众问题

每个 OBS/KF 资产必须回答一个问题，例如：

- 谁先接触？
- 包在哪里？
- 为什么这颗烟重要？
- 谁能补到谁？
- 只剩多少时间？
- 现场解说为什么撤回判断？

没有观众问题，就不加 UI 或俯视图。

### 2. 选择观察者视角

- 第一人称：看操作与准星；
- 自由镜头：看两方空间关系；
- 俯视图：看轮转、道具和补枪链；
- 回放：看时间顺序与证据；
- 现实切回：看人物承担的后果。

### 3. UI 后期硬锁

生成资产只提供版式与空槽。精确比分、选手名、地图名、经济、击杀栏、字幕和赛务字段全部后期合成。不要要求模型生成长文字。

### 4. 选手信息隔离

观察者 UI 和太监解说面向观众。不得在游戏战场内画成角色可见全息界面，也不得让解说声音成为角色听见的旁白。

## 太监解说工作流

### 1. 岗位分工

- `唱局监`：实时事实、人数、时间、掉包、残局；
- `评策监`：经济、道具、站位、补枪和下一轮代价；
- `掌镜监`：切镜与回放；
- `录局监`：时间戳与证据索引；
- `洛遥音`：直播制作、采访、剪辑和公共口径。

### 2. 尊严与语言硬锁

太监是专业岗位，不使用尖嗓、娘化、身体羞辱、猥琐或谄媚刻板印象。现代 CS 口语占主体，宫廷词不超过调味比例。

### 3. 合法信息

填写：

```text
EUNUCH_CAST_ROLE:
KNOWN_INFO:
FORBIDDEN_INFO:
LINE_FUNCTION:
AUDIO_PRIORITY:
OBSERVER_VIEW:
```

无法说明信息来源时，删除该句。

### 4. 声音与画面

太监解说可以用 J-cut 带入游戏战场，用 L-cut 把枪声带回现实赛台。关键脚步、拆包音、队内报点和枪声优先，解说必须让位。

### 5. 解说 QC

- 是否先报事实再判断？
- 唱局与评策是否重复同一句？
- 是否泄露队内或未来信息？
- 宫廷口彩是否妨碍专业口语？
- 是否靠尖嗓和身体梗制造人物？
- 现场判断与赛后证据是否分栏？

## 失败诊断

- **地图失败**：看不懂战术地理 → 回到 A/B/MID 和回防，不加装饰。
- **武器失败**：结构错误 → 删除纹样词，先锁功能轮廓和机械关系。
- **化身失败**：像换脸陌生人 → 回到身份母版字段，不继续堆职业词。
- **动作失败**：手部和武器坍塌 → 拆成单动作关键帧，使用首尾状态。
- **层级失败**：UI 像角色外挂 → 明确 OBS 面向观众并从游戏世界移出。
- **解说失败**：像宫廷小品 → 删除嗓音/身体梗，重写事实、因果和权限。
- **文字失败**：乱码 → 清空文字，保留后期安全区。
- **连续性失败**：同枪/同人跨镜漂移 → 固定基础型号、角色母版和参考图。

不得用“再随机生成一次”代替定位问题。

## 交付前总检

- `ASSET_ID` 是否存在于资产清单？
- 资产是否只属于一个主类型和一个主层？
- 战术功能是否写清？
- 地图是否原创且可打？
- 武器是否现代、可操作且结构准确？
- 比赛化身是否与空手母版分流？
- 太监解说是否专业、有权限边界和人物尊严？
- 精确 UI 是否留后期合成？
- 是否无现实队标、赞助商、真人肖像复刻、随机文字和伪汉字？
- 当前资产通过后才进入下一资产，不批量跳过 QC。
