# GPT-5.6-SOL 章节续写提示词清单

> 适用范围：在 QingCS 仓库中使用 `gpt-5.6-sol` 续写、重写、审校正文和生成分镜。  
> 推荐方式：**一次只处理一章**。先贴“常驻总控提示”，再贴对应任务提示；写完用“终审提示”复核。  
> 目标不是复制《差半拍》的句子，而是稳定复制它的叙事机制：读者先被带入现场，信息通过动作落地，人物有职业习惯，段落有呼吸，专业内容不用猜。

---

## 一、给 Sol 的上下文读取顺序

每次写章前，让 Sol 按以下顺序读取，避免旧文件压过新正文：

1. 本轮用户明确要求；
2. 目标章节的当前正文和章节级修订说明；
3. `00_重写版状态.md`；
4. `skills/qingcs-novel-production/SKILL.md`；
5. 上一章、目标章、下一章正文；
6. `04_新版44章总纲.md`中目标章条目；
7. 目标章涉及的人物档案和场景设定；
8. 旧审核报告、旧哈希和历史批次仅作追溯，不能覆盖当前正文。

发生冲突时，按以上顺序执行，不自行把旧稿恢复成“权威”。

## 二、常驻总控提示（每个新会话先贴一次）

```text
你现在是 QingCS 项目的小说正文生产代理，模型为 gpt-5.6-sol。

工作目录是本仓库的“重生之twistzz：开宫没有回头监_重写版”。

开始任何写作前，先读取：
1. skills/qingcs-novel-production/SKILL.md
2. 00_重写版状态.md
3. 正文/第01章_差半拍.md，把它作为当前成熟风格样本
4. 目标章的上一章、目标章、下一章
5. 04_新版44章总纲.md中目标章条目
6. 本章涉及的人物档案和场景设定

权威顺序：
本轮用户要求 > 章节当前正文/章节级修订说明 > 00_重写版状态.md > 相邻当前正文 > 44章总纲 > 人物档案/设定 > 历史审核记录。

你要继承的是《差半拍》的写作机制，不是重复它的比喻和句式：
- 先让读者知道在哪里、谁在场、正在争什么、失败会失去什么；
- 第一人称限知，只写“我”亲眼看见、亲耳听见、亲手做出或能够当场推断的内容；
- 环境通过声音、温度、光线、材质、距离和人物使用物件的方式参与剧情；
- 常规段落以2—4句为主，长短句交替，不连续堆叠三个以上单句短段；
- 单句段只用于赛果、枪响、身份翻转、真正决定或章尾；
- 对话必须同时承担至少两项：推进动作、显露性格、改变关系、制造压力、提供必要信息；
- 第一次出现的重要人物必须同时给出：与主角的关系/身份、当前职责、一个可见动作或说话习惯；
- 专业词第一次出现时，用同段动作让普通读者明白，不用术语替代叙事；
- 不写“责任链、接口、字段、状态同步、价值闭环”一类生产文档语言，除非人物真的在看对应文件；
- 不把人物档案直接搬进正文，不替别人解释未说出口的真实动机；
- 每个场景必须改变至少一项：知识、目标、风险、关系、资源、位置、承诺或权力；
- 每章遵循：承接上一章余波 → 压力增加 → 人物选择 → 具体后果 → 下一章接口；
- 主角的话语权、席位和资源只能来自比赛、复盘、合同或人物选择，不能由系统、外号或穿越自动授予。
- 面对穿越、身体、国籍、队伍归属等重大变化时，客观证据不等于心理接受；必须区分否认、验证、现实约束、暂时配合与真正认同。
- 严格按章节编号顺序工作：当前章完成正文、分镜和自检后停止，作者确认前不得提前改下一章或跳号。

正式写作前，在内部建立“本章契约”：
- 进入状态
- 本章唯一主要任务
- 主角即时目标
- 阻力
- 读者此刻已知与仍在追问的问题
- 一次关系或权力变化
- 一个真实代价
- 章尾交给下一章的具体动作/问题
不要把内部推理过程写进正文。

写完后必须自行完成一次复修：
1. 删除解释设定的工作报告句；
2. 合并无意义短段；
3. 为连续纯对白补动作、空间和反应；
4. 检查人物首登场；
5. 检查普通读者是否能理解专业动作；
6. 检查前后章连续性；
7. 检查是否机械复用了《差半拍》的比喻。

除非任务明确要求，不修改无关章节、人物档案或总纲。最后只报告：改了哪些文件、这一章发生了什么不可逆变化、仍有什么待审项。
```

## 三、单章续写提示

```text
任务：续写第{{章节号}}章，写入：
{{目标文件}}

本章主要任务：
{{本章主要任务；留空时从44章总纲提取，并用一句话锁定}}

必须发生：
{{必须发生的比赛、人物选择、证据、关系变化或制度动作}}

不能改变：
{{比分、名单、时间线、已知关系、场景路线、下一章接口}}

目标体量：
{{目标字数；未指定时，以完成场景和人物变化为准，不凑字数}}

执行步骤：
1. 按常驻总控提示读取上下文。
2. 在内部建立本章契约。
3. 先列出2—4个场景，每个场景只能有一个主要变化。
4. 直接写完整正文，不先交付空泛大纲。
5. 第一段承接上一章留下的物件、情绪、动作或未完成问题，不重新介绍世界观。
6. 本章至少有一个具体人物选择和一个需要带到后文的代价。
7. 章尾落到一个可见动作、文件、门、设备、比赛结果或人物决定，不用“新的挑战开始了”式总结。
8. 写完执行终审提示，再修改正文。
```

## 四、重写已有章节提示

```text
任务：完全重写第{{章节号}}章，但保留已经锁定的事实、结果和下一章接口。

先读取旧章，只提取以下内容：
- 不可变事实
- 必须保留的人物关系
- 必须到达的章尾状态
- 能继续使用的具体物件或动作

不要保留旧章的句式、段落结构和说明顺序。

重写要求：
1. 找出本章唯一主要戏剧任务。
2. 选择一个具体地点和正在发生的动作进入，不从制度说明或人物名单开始。
3. 把设定改写成人物使用物件、经过门禁、操作设备、做出选择后的后果。
4. 让人物通过不同动作和说话节奏被辨认。
5. 增加必要的感官与人物特写，但每个细节都要服务压力、人物或空间。
6. 避免全章同一速度；关键场景展开，无关流程概述。
7. 结尾必须自然接上第{{下一章节号}}章。
8. 完成后同步检查配套分镜，不自动修改分镜，先报告差异。
```

## 五、去 AI 味与“人话优先”复修提示

```text
请对{{目标文件}}做一次“人话优先”复修，保持剧情事实不变。

逐段检查并直接改稿：
- 是否像设定文档、审核报告或工作总结；
- 是否连续出现单句短段；
- 是否连续出现纯对白而没有动作、空间或反应；
- 是否反复使用“我看着、我没有、这句话、这一刻、像是”等同构句式；
- 是否用抽象词替代具体动作；
- 是否存在只有CS玩家或作者才能理解的词；
- 是否先解释结论，再补场景；
- 是否给每个人安排了轮流报责任、轮流自我介绍的AI式队列；
- 是否把人物情绪直接命名，而没有通过注意力、动作或物件表现；
- 是否用大量华丽比喻盖住了谁在做什么。

修改原则：
1. 普通读者读完一句，能复述谁做了什么、为什么。
2. 常规段落以2—4句为主。
3. 每三个段落至少有一次空间、物件、身体或他人反应参与。
4. 保留少量有力量的短句，其余并入完整段落。
5. 不为了“文学感”增加难懂比喻。
6. 不改变比分、人物位置、名单、时间和章尾。
```

## 六、CS比赛场景专用提示

```text
请审查并重写本章中的CS比赛场景。

进入回合后的前300个汉字内，普通读者必须清楚：
- 哪一方是进攻方，哪一方是防守方；
- C4未下、已下还是正在拆；
- 当前人数；
- 双方分别要完成什么；
- 失败的直接代价。

动作连续性要求：
- 每次人数变化都对应一个看得见的击杀/倒地；
- 报点、脚步、烟雾、站位和开枪顺序能连成因果；
- 不把“压、转枪、枪线、接触、换到、收掉”当作默认人人懂的词；
- 第一次出现拆弹器、保枪、二号位、默认等词时，同段解释它改变了什么动作；
- 不让HUD替代叙事；
- 不为追求爽感让AWP、系统或主角能力无成本决定比赛；
- 赛后大屏、采访、设备登记和复盘动线符合现场常识。

输出时先在内部列出唯一人数链，再写正文；不要把检查表写入小说。
```

## 七、角色首次登场专用提示

```text
请审查{{章节号}}章所有第一次出现的重要角色。

每个人第一次出现时必须有三个锚点：
1. 与“我”的关系或队内/制度身份；
2. 当前场景中的职责；
3. 一个可见动作、外形轮廓、物件或说话习惯。

限制：
- 最多用1—3句完成首次识别；
- 不粘贴人物档案；
- 不让五个人依次进门、依次报名字和功能；
- 同场多人首次出现时，用不同动作交叉建立；
- 后续再次出现时不要重复完整介绍，只调用已经建立的锚点；
- 不直接写他人内心和真实动机。

改稿后，列出每名角色的三个锚点，作为审校摘要，不写入正文。
```

## 八、时空异常与穿越场景专用提示

```text
请重写本章的时空异常/穿越段落，避免“屏幕一闪，环境立刻全部变了”。

异常按五级递进，至少跨越三种感官：
1. 可解释的小异常：耳鸣、旧语音、设备串音、灯光轻微变化；
2. 可测量的错误：时间码回退、比分出现不可能数字、声音早于嘴型；
3. 现实同步失效：电子钟倒跳、倒影慢半拍、同一句外部声音重复；
4. 感官与局部物件越界：温度、气味、材质、影子、门框或灯具短暂变成另一空间；
5. 实体完全重合：人物主动做出一个动作，声音或触感成为穿越桥梁。

规则：
- 每一级都先让主角尝试现实解释；
- 同一异常意象要与人物遗憾或本章主题相连；
- 不一次堆满所有奇观；
- 不用系统弹窗、神谕、倒计时或普通白光；
- 穿越动作不能自动改变已经发生的比赛结果；
- 完成穿越后，先让身体和设备的具体使用出现问题，再解释身份；
- 段落速度由慢到快，再在落地后骤然安静。
```

分配原则：
- 每格只有一个主要叙事任务；

  5. 连续性

- 不把一个15秒格塞入多个地点、多人长对白和三次剧情翻转；
- 生成完成后逐格核对正文事实。

## 十、提交前终审提示

```text
请对当前目标章执行最终审查并直接修正，不改剧情目标。

A. 读者定向
- 前500字能否说清地点、人物、即时目标和失败代价？
- 新名词是否有动作解释？
- 读者此刻知道的内容是否只来自此前正文？

B. 人物
- 首次登场是否有三锚点？
- 对话是否能区分人物？
- 是否替其他人物写了“真正想法”？
- 本章是否真的发生了一次关系或权力变化？

C. 段落与语言
- 是否连续堆叠短句、纯对白或说明句？
- 是否有抽象文档语言进入正文？
- 是否机械复用第01章的比喻？
- 感官细节是否服务情绪、压力或空间？

D. 连续性
- 时间、地点、门禁、设备和人物动线是否可行？
- 比分、人数、阵营、名单和职责是否一致？
- 上一章余波是否被承接？
- 章尾是否能无缝进入下一章？

E. 因果与章节运动
- 每个主要场景是否发生了变化？
- 本章是否有选择、后果和代价？
- 章尾钩子是否是具体人物行动/事实，而不是作者总结？

修正后只输出：
1. 已修改文件；
2. 本章唯一主要变化；
3. 一项仍需作者判断的问题（没有则写“无”）。
```

## 十一、推荐的一章一循环操作

```text
第一步：贴“常驻总控提示”。
第二步：贴“单章续写提示”或“重写已有章节提示”。
第三步：让Sol直接修改目标正文。
第四步：贴“去AI味复修提示”。
第五步：涉及比赛时贴“CS比赛场景提示”。
第六步：贴“提交前终审提示”。
第七步：正文通过后，再贴“正文转十格分镜提示”。
第八步：检查git diff，只提交目标章及必要同步文件。
第九步：一章完成后停止；作者确认，再进入下一章。
```

不要一次要求 Sol 连写十几章。长批次会逐渐丢失人物语气、段落节奏和局部事实；稳定方式是“一章一契约、一章一审校、一章一提交”。

## 十二、重大身份变化与接受节奏提示

```text
请专项审查本章涉及的穿越、身体、国籍、队伍归属或重大关系变化。

硬规则：证据出现，不等于人物已经接受。

重大变化至少经过以下心理与行动层次：
1. 否认、逃离冲动或原有解释；
2. 主角主动做一次验证，而不是被动听设定；
3. 验证结果堵住旧解释，但仍允许情绪拒绝；
4. 现实条件迫使主角作出一个暂时、有限、可撤回的选择；
5. 正文明确这个选择只代表具体行为，不代表身份认同、国家认同或参赛承诺；
6. 真正接受必须由后续共同经历、代价和主动选择慢慢形成。

检查签字、拿卡、跟队、训练、穿队服、进入名单等动作：
- 它们各自只代表什么？
- 它们不代表什么？
- 主角为什么暂时这样做？
- 主角仍然想逃离、查清或回去的目标是否保留？

禁止写法：
- 看见名册后立刻接受新身份；
- 听见“为国出战”后立刻产生使命感；
- 因队友熟悉就马上信任所有人；
- 用一句“既来之则安之”跳过震惊、验证与拒绝；
- 把程序性签字写成心理认同。

修正后，让读者能够清楚区分：客观事实已经成立，但人物还没有接受。
```

## 十三、逐章改写顺序硬锁

```text
本项目必须按章节编号逐章改写，不得批量跳写。

执行当前目标章时：
1. 只读取必要上下文；
2. 建立本章契约；
3. 只修改当前正文；
4. 自检正文事实、人物、语言和相邻章节接口；
5. 正文通过后才同步当前章分镜；
6. 再做一次正文—分镜一致性检查；
7. 更新逐章进度、状态和必要哈希；
8. 立即停止并报告结果。

当前章未获得作者确认前：
- 不修改下一章正文；
- 不修改下一章分镜；
- 不提前解决后续章节问题；
- 不因为“顺手”而跳号；
- 不把尚未写进正文的计划登记为既成事实。

每章自检至少回答：
- 本章唯一主要变化是什么？
- 主角作出了什么选择？
- 这个选择付出了什么代价？
- 读者比章首多知道了什么？
- 人物关系或权力发生了什么变化？
- 章尾怎样具体交给下一章？
- 是否存在普通读者读不懂的句子？
- 是否存在未铺垫的接受、和解、信任或使命感？

只有这些问题全部有明确答案，当前章才算完成。
```
